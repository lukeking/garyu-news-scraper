# 產出的文字：短核心

這份是 user 層規則 `output-conventions` 的短核心，逐字照抄自維護者的規則庫（`templates/repo-rules/output-conventions-core.md`），
給讀不到 user 層規則的雲端 session（claude.ai/code、手機 app、`claude --cloud`、雲端排程）用。不在這個 repo 裡改它：改正本，再照抄過來。
同一個 session 也載入了 user 層的 `output-conventions` 時，以那一份為準。

## 紀錄的寫法：記整理後的結論，不寫誰說了什麼

範圍是會留下來的文字：commit 訊息、PR 內文與留言、文件、註解與 docstring、測試訊息、handoff、Linear、memory。

- 不寫誰說了什麼、誰裁示。定了的寫「已定＋日期」；還沒定的寫「提案」或「未定」；還沒定案的偏好寫「傾向…（未定案，日期）」。
- 還沒定、要有人決定的事，不寫由誰決定。人本身是流程一環的地方（通知誰、誰去外部 console 操作）寫「維護者」。
- 記整理後的結論與它的脈絡，不拿原話代替整理。原話留不留看三問：它有沒有帶來結論以外的資訊；那個資訊為什麼整理不進結論；
  它跟結論有沒有解讀上的衝突。
- 讀不懂原話或舊紀錄的意思，先問，不猜著改寫。
- 出處指到東西：PR、spec、BACKLOG id、commit、檔案與節，不指到人。
- 這一節不是只向前適用：既有內容要清，分批做，範圍與進度記在這個 repo 的 BACKLOG。改不了的不追：git log、已 merge 的 PR。
- 沒有狀態詞、沒有日期的舊否決（「不用 X」），不當成已定的關閉；眼前的工作需要 X 時先問。

## 命名不用拼音

分支名、識別字、檔名、commit、文件都不出現拼音。只能用 ASCII 的地方把中文詞翻成英文（`其他` → `other`）；可以放中文的散文直接寫繁體中文。
品牌與專有名詞不音譯：用中性的 id（PR、issue 編號），或抽象成英文概念（某家餐廳 → `restaurant`）；都不合適就先問。

## 序列編號用 ASCII

不用 Unicode 的序列編號字元（圈號、括號數字、帶點數字、羅馬數字、圈字母），改用 `1.`、`(1)`、`1)`、`- `。

## 標籤用完整的字

- 描述項目、等級、組別或行為時，寫完整的字或片語，不用頭文字加編號：寫 `實測` 不寫 `E1`。同一份文件裡的流水號，每條給一個短名。
- 會被讀成另一個意思的詞也一樣。給 user 讀的題目、選項、表格欄名與要 user 照做的指示裡，兩個字的縮寫詞展開成短語（「准駁」寫「核准或駁回」）；
  一個說法指得到兩種動作時，寫出是哪一種。判準是會不會被讀成另一個意思，不是語域。
- 豁免：追蹤編號（`<專案代碼>-YYYYMMDD-xxx`），與外部工具自己的格式（spec-kit 的 `T001`、`FR-`、`SC-`）。
