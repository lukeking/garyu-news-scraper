# 實驗：`gemini-3.8-flash`（現行，已被自動換上）與 `gemini-4-argon`

**日期：** 2026-10-19（TW）  **分支：** `docs/model-quality-3p8-argon`  **BACKLOG：** `GNS-20261015-8pg`
**問題：** prod 的 `GEMINI_MODEL_NAME` 寫 `gemini-3.7-flash`，但 2026-10-08 起 API 把 3.7 自動轉給 3.8，
所以之後的週報是 3.8 產生的，沒有評比過。要回答兩件事：3.8 比 3.7 有沒有退步；argon 值不值得它的價錢。
據此決定 prod 的值：留在 3.8、釘回 `gemini-3.6-flash`，或換 argon。

這是 PR `#74`、`#90` 那套 framework 的第三輪。

---

|---|---|---|---|

## 方法（route A，與 PR `#90` 相同；差別如下）

- **不重新凍結**：沿用 PR `#90` 的快照（`../model-quality-3p6flash-vs-3p7flash/data/q_snapshot.json`，
  週次 2026-08-10），3.7 的輸出也讀那裡的存檔。10-19 實測：`analyze_hot_topic` 在 `770ed2a` 與現在送出的
  prompt（含 system prompt）三桶逐位元組相同；生成參數只差 API key 從網址移到 header。
- **兩組比較**：3.7（存檔）對 3.8、3.8 對 argon。每模型每桶 3 次，盲評＋位置對調，每組 18 次裁決。
- **`modelVersion`**：每次回應都記下來，開頭對不上要求的模型就停下（fail closed）。3.8 就是這樣無聲換掉 3.7 的。
- **裁判**：與 PR `#90` 相同（`gemini-2.5-pro`），3.8 對 3.7 那組才能跟 PR `#90` 比。argon 比裁判強、又同屬
  Gemini 家族，所以 argon 那組不論結果，都由 Claude 在 session 裡做跨家族抽查（Luke 10-19 裁示）。

## 成本：算全部呼叫端（Luke 10-19 裁示）

`GEMINI_MODEL_NAME` 同時給熱點／彙整、FFXIV 的 `analyze_article`、auto-KB 用，換它等於三條一起換。
品質只量熱點；成本三條都算。

- **每週呼叫次數**（實測，09-21～10-19 五次週報與近 3 次 auto-KB 的 log）：熱點 1–2 次＋彙整 1 次、
  FFXIV 20 次、auto-KB 0 次（近 3 週都「沒有未知術語，跳過 Gemini」）。
- **FFXIV 的單次成本**：即時抓 FFXIV 來源，照週報的篩選取前 5 篇，兩個模型各跑一次 `analyze_article`（實測，
  只量成本、不評品質）。FFXIV 的 prompt 帶整份知識庫，所以要讀正式庫的 `knowledge_base` 表（只 select）。
- **彙整的單次成本**用熱點代替（推論：彙整的輸入較多，會低估）。

## 決策閘門（沿用 PR `#90` 的階梯，每組各判）

| 階 | 判準 | 意義 |
|---|---|---|
| **Gate** | generateContent 可用、`modelVersion` 相符、格式無退步、無杜撰引證退步 | 不過就不換，回報退步 |
| **L1 非劣** | 盲評勝率 40–60%，且沒有任何一軸落後超過 0.3 | 只在有營運理由（成本、支援期限）時才換 |
| **L2 明確勝出** | 勝率 ≥ 65%，或逐軸平均領先 ≥ +0.3 | 以品質為由換 |
| **成本** | 每份報告與每月的實測成本 | ≥ L1 且更便宜就換；更貴要到 L2 |

- 3.8 對 3.7：3.8 已經在 prod。過不了 Gate 或 L1 時，退路是釘回 `gemini-3.6-flash`（沒有 deprecated，PR `#90` 判定與 3.7 平手）。
- 3.8 對 argon：argon 比較貴，要到 L2，而且換完的月成本要在 NT$300 的上限內。
- 不論結果，prod 的變數都要改成明寫的值——現在寫的 3.7 已經不是實際在跑的模型。

**證據等級**：可用性、`modelVersion`、機械檢核、成本、token 量是實測；品質分數是判斷（模型裁判只答相對差距）。

## 結果（2026-10-19 跑；全部數字在 `data/q_report.md`）

**決策：留在 `gemini-3.8-flash`，prod 的 `GEMINI_MODEL_NAME` 於 10-19 明寫成 `gemini-3.8-flash`（`gh variable get` 讀回逐字相符）。**
3.8 對 3.7 沒有退步；argon 過不了 L1。

執行：生成 18 次（`modelVersion` 全部相符）、裁判 36 次（全部可解析）、FFXIV 樣本 10 次，沒有失敗。
實際花費約 US$1.82（裁判 $1.53），在核准的估算內。

### 3.7（存檔）對 3.8

- 勝負：3.8 10 次、3.7 3 次、平手 5 次。總平均 4.04 → 4.23（+0.19）。
- 逐軸：文本依據 +0.44、因果解構深度 +0.42、轉譯紀律 +0.19、觸發制紀律 −0.11、格式 5.00＝5.00。
- 閘門：Gate 通過；L1 非劣達成（沒有任何一軸落後超過 0.3）；L2 沒到（勝率 56%、總平均 +0.19）。
- 不需要釘回 `gemini-3.6-flash`。

### 3.8 對 argon

- 勝負：argon 10 次、3.8 7 次、平手 1 次。總平均 4.39 → 4.13（−0.26）。
- 逐軸：觸發制紀律 **−1.22**、文本依據 **−0.50**、因果解構深度 +0.33、轉譯紀律 +0.11。
- 閘門：L1 沒過（兩軸落後超過 0.3）。argon 比較貴，依閘門要到 L2 才換，所以不換。
- **跨家族抽查**（Claude 盲評 run1 三桶，`data/spot_claude.md`，揭盲前寫定；對照表 `data/spot_key.json`）：
  argon 2 勝（B2、B3）、3.8 1 勝（B1）。與裁判一致的部分：argon 會過度觸發（B1 沒有任何統計宣稱，仍觸發 §三）。
  不一致的部分：抽查裡 argon 的引證比較完整（B2 兩個子題都處理且逐句標引證）。
- **裁判輸入的落差**：生成拿每篇摘要前 600 字，裁判只看到前 200 字（PR `#74` 起都是這樣）。argon 每份引證 12.6 處，
  3.8 是 4.1 處，所以文本依據的 −0.50 可能有一部分來自這個落差（推論）。就算這一軸翻過來，觸發制紀律的 −1.22
  有抽查佐證，總平均也到不了 L2 的 +0.3，結論不變——因此沒有重評（Luke 10-19）。修正留給下一輪（BACKLOG `GNS-20261019-1vk`）。

### 成本與延遲（實測）

| | $/熱點報告 now／later | 均 thinking | 秒／熱點報告 | $/FFXIV 篇 now／later | 月成本（全部呼叫端）now／later |
|---|---|---|---|---|---|
| `gemini-3.7-flash`（PR `#90`） | $0.0153 | 1231 | 7.1 | — | — |
| `gemini-3.8-flash` | $0.0123／$0.0246 | 2440 | 28.1 | $0.0074／$0.0147 | $0.80／$1.60 |
| `gemini-4-argon` | $0.0104／$0.0207 | 0 | 21.4 | $0.0106／$0.0212 | $1.06／$2.12 |

- argon 的回應沒有 `thoughtsTokenCount`，14 次的 `totalTokenCount` 都剛好等於輸入＋輸出，所以照 API 回報沒有 thinking 計費；
  單價是 3.8 的 2.67 倍，月成本只多約 32%。兩者都遠低於 NT$300 的月上限。
- 月成本＝每週（熱點＋彙整 3 次 × 熱點單價 ＋ FFXIV 20 次 × FFXIV 單價）× 4.35。彙整用熱點單價代替（推論，會低估）；
  auto-KB 近 3 週 0 次，照 0 算（Luke 10-19；設計上每週最多批次 1 次，等日文論壇接進來、開始出現未知術語時再量）。
- **3.8 比 3.7 慢**：熱點報告 28 秒對 7 秒，thinking 約兩倍。週報裡 FFXIV 那 20 篇的分析時間，3.7 時期（09-21／09-28／10-05）
  是 218／207／199 秒，3.8 時期（10-12／10-19）是 292／352 秒——週報耗時從 10-12 起上升，時間點與自動轉送吻合（推論）。
