# Data Model: Site UX Polish

**Feature**: `specs/003-ux-polish/spec.md`
**Date**: 2026-05-04

## Entities

### 1. Article (existing, extended)

Stored in Supabase `articles` table. No new columns added; `content_fingerprint` is expanded to cover all articles.

| Field | Type | Change | Notes |
|-------|------|--------|-------|
| `id` | uuid | unchanged | Auto-generated primary key |
| `week_id` | text | unchanged | e.g., `"2026-W18"` |
| `title` | text | unchanged | Raw article title |
| `link` | text | unchanged | Upsert key; unique per article |
| `source` | text | unchanged | Source name |
| `published` | text | unchanged | RFC 2822 date string |
| `summary` | text | unchanged | Short summary |
| `analysis` | jsonb | unchanged | AI analysis output |
| `content_type` | text | unchanged | `"traffic"` or `"ffxiv"` |
| `content_fingerprint` | text | **expanded** | Now sha256(normalized_title_only) for ALL articles; previously only set for URL-less articles |
| `created_at` | timestamptz | unchanged | Supabase auto-set |

**Validation rules**:
- `content_fingerprint` MUST be a 64-character hex string (sha256 output)
- `content_fingerprint` MUST be computed from `re.sub(r'[^\w一-鿿぀-ヿ]', '', title.lower().strip())`
- `content_fingerprint` may not be null after this feature is deployed

**State transitions**: Articles move from "candidate" (collected) → "excluded by freshness" (logged, not stored) → "stored" (Supabase). The freshness filter is applied before storage; there is no stored representation of excluded articles.

---

### 2. TitleFingerprint (computed, no new table)

A derived value, not a separate entity. Computed in `filter.py` and stored in `Article.content_fingerprint`.

| Attribute | Value |
|-----------|-------|
| Algorithm | sha256 |
| Input | `re.sub(r'[^\w一-鿿぀-ヿ]', '', title.lower().strip())` |
| Output | 64-character hex string |
| Computed in | `src/filter.py::title_fingerprint(article)` |
| Stored in | `articles.content_fingerprint` (Supabase) |
| Queried by | `src/storage.py::get_existing_title_fingerprints()` |

**Uniqueness**: Not enforced at DB level; duplicate fingerprints cause article exclusion at filter time (this is the intended behavior — dedup).

---

### 3. DismissedArticle (browser localStorage, no server representation)

| Attribute | Value |
|-----------|-------|
| Storage | Browser localStorage |
| Key (traffic site) | `dismissed-traffic` |
| Key (FFXIV site) | `dismissed-ffxiv` |
| Value format | JSON array of URL strings: `["https://...", "https://..."]` |
| Scope | Per device, per browser |
| Cleared by | User clicking "清除過時標記" |

**Lifecycle**:
1. User clicks "標記過時" → article URL appended to localStorage array → card hidden immediately
2. Page load / week switch → localStorage array read → matching articles excluded from rendered list
3. User clicks "清除過時標記" → localStorage array set to `[]` → all articles re-render

**Edge cases**:
- localStorage unavailable (private mode, storage full): card hidden for session only; no error thrown
- URL contains query parameters: stored and matched as-is (exact string match)

---

### 4. ThemePreference (browser localStorage, no server representation)

| Attribute | Value |
|-----------|-------|
| Storage | Browser localStorage |
| Key | `theme` |
| Value | `"light"` or `"dark"` |
| Default (no stored value) | Derived from `window.matchMedia('(prefers-color-scheme: dark)').matches` |
| Scope | Per device, per browser, per site (separate Cloudflare Pages deployments) |

**Applied via**: `data-theme` attribute on `<html>` element. CSS overrides via `[data-theme="dark"]` selector.

### 5. FFXIVFeed (static file, generated by pipeline)

| Attribute | Value |
|-----------|-------|
| Path | `pages/ffxiv/feed.xml` |
| Format | RSS 2.0 with Atom namespace |
| Generated by | `src/publisher.py::build_feed()` called from `FFXIVCategory.publish()` |
| Content | Articles from at most the 3 most recent FFXIV weekly runs |
| Max items | 60 (existing cap in `build_feed()`) |
| Feed title | `最終幻想XIV 週報` |
| Feed description | `每週自動彙整 FFXIV 遊戲相關資訊，含 AI 摘要與重點分析` |
| Language | `zh-tw` |

**Invariant**: `feed.xml` is always generated, even if the article list is empty (produces a valid RSS document with no `<item>` elements).

### 6. KBMissMarker (ephemeral, within Article.analysis JSONB)

Not a separate DB entity — a pattern that may appear within the `analysis` JSONB field of stored FFXIV articles. Produced by the AI analyzer when a game term is absent from `knowledge-base.md` at analysis time.

| Attribute | Value |
|-----------|-------|
| Pattern | `[[term]]` where `term` is the unresolved JP/EN game term |
| Location | Any text-value field within `articles.analysis` (JSONB) |
| Detected by | `re.findall(r'\[\[([^\]]+)\]\]', json.dumps(analysis))` |
| Resolved by | `scripts/resolve_kb_misses.py` after KB update |
| Persistence | Remains in Supabase until resolved by the re-resolution job |

---

### 7. KBReResolutionJob (GitHub Actions workflow, no DB entity)

| Attribute | Value |
|-----------|-------|
| Trigger | Push to `main` with path filter `knowledge-base.md` |
| Workflow file | `.github/workflows/resolve-kb-misses.yml` |
| Script | `scripts/resolve_kb_misses.py` |
| Supabase query | `SELECT id, analysis FROM articles WHERE content_type = 'ffxiv' AND analysis::text LIKE '%[[%'` |
| Resolution | KB string replacement on serialized JSON; `json.loads()` back before UPDATE |
| KB source | `knowledge-base.md` parsed at job runtime (JP Term → TW Term dict) |
| Secrets required | `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (existing) |
| Output | Supabase UPDATE per resolved article; KB MISS warning per unresolvable term |

**Lifecycle**:
1. KB PR merged to `main` → GH Actions triggers
2. Script reads updated `knowledge-base.md` → builds JP→TW dict
3. Queries Supabase for articles with `[[` in analysis
4. For each article: replaces all resolvable `[[term]]` markers → UPDATEs row
5. Logs KB MISS for any still-unresolvable markers
6. Readers see resolved content immediately (Worker API is dynamic)

---

## Relationships

```
Pipeline run
  └─ collects Articles (raw)
       └─ freshness_filter() excludes stale Articles (logged only)
            └─ filter_and_deduplicate() dedups within run
                 └─ upsert_articles() stores Article with content_fingerprint (TitleFingerprint)
                      └─ analysis JSONB may contain KBMissMarkers if KB was incomplete

knowledge-base.md pushed to main
  └─ GH Actions triggers KBReResolutionJob
       └─ loads KB → JP→TW dict
            └─ queries Supabase for Articles with KBMissMarkers
                 └─ resolves markers via string replacement → UPDATEs Article rows
                      └─ emits KB MISS warning for still-unresolvable markers

Browser session
  └─ reads Article list from Worker API (dynamic, reflects latest Supabase state)
       └─ filters by DismissedArticle.urls (localStorage)
            └─ renders visible Articles (KBMissMarkers resolved if KB job has run)
                 └─ user may DismissArticle → updates DismissedArticle.urls
                 └─ user may toggle ThemePreference → updates localStorage
```
