# Data Model: Buffer List 雜訊分流呈現層

**Feature**: 011-buffer-noise-triage | **Date**: 2026-07-21

## 不變式

**本功能不新增任何資料庫欄位、資料表或遷移。** `articles` 表維持原樣。這是 FR-001／FR-001a 的直接結果，也是本設計最重要的性質——它讓功能能對全部 11 週歷史資料同等生效，且隨時可完全撤除。

## 實體一：來源倍率設定（唯一的持久化新增）

**存放位置**：Cloudflare Worker 變數 `SOURCE_UPTAKE_JSON`，值來自 GitHub production environment variable，經 `deploy-worker.yml` 的 `vars:` / `env:` 區塊注入。

**形狀**：

```json
{
  "threshold": 0.5,
  "window": "2026-W22..2026-W29",
  "measured_at": "2026-07-21",
  "baseline_uptake": 0.195,
  "sources": {
    "Google News 機車交通":     { "multiple": 0.41, "n": 186 },
    "Google News 重機":         { "multiple": 0.31, "n": 17 },
    "火花羅":                   { "multiple": 0.31, "n": 17 },
    "中時新聞網":               { "multiple": 1.33, "n": 165 },
    "Google News 機車事故":     { "multiple": 1.69, "n": 27 },
    "Google News 中央社機車":   { "multiple": 2.67, "n": 21 }
  }
}
```

**欄位規則**：

| 欄位 | 規則 |
|---|---|
| `threshold` | 倍率門檻。`multiple < threshold` 判為雜訊。可獨立調整而不需重測（FR-005a） |
| `window` / `measured_at` / `baseline_uptake` | 可追溯性欄位（FR-005）。不參與推導，但 MUST 存在——沒有它們就無法判斷數值是否過期 |
| `sources[*].multiple` | 該來源採用率 ÷ `baseline_uptake`。非負浮點數 |
| `sources[*].n` | 量測樣本數。MUST ≥ 15（FR-005d）；低於門檻者 MUST NOT 出現在此物件中 |

**驗證規則**：

- 設定缺失、無法解析、或 `sources` 為空 → **全部文章視為非雜訊**。降級功能靜默停用，列表退回現況行為。理由：設定錯誤不該讓內容消失。
- 來源名稱未出現在 `sources` → 該來源非雜訊（FR-006）。這是 24 個樣本不足來源與所有未來新增來源的預設路徑。
- 名稱比對 MUST 為完全相等，MUST NOT 為子字串比對。`sources_traffic.yml` 中存在共用前綴的來源名（多個 `Google News *`），子字串比對會誤中。

**已知待補**：六個 07-20 新增來源（`GN 交通安全教育`／`停讓行人`／`機車待轉`／`禁行機車`／`處罰條例`／`UDN 聯合報`）在 07-27 首次週報前無法量測，因此不在初版設定中，一律走預設非雜訊。

**需要人工判斷的一筆**：`火花羅` 倍率 0.31 落在雜訊側，但它是**手動挑選的 YouTube 頻道**，不是自動產生的搜尋查詢。影片內容不易與新聞文章聚成熱點群集，低採用率可能反映的是型別差異而非價值低落。量僅 17 篇，降級與否對版面影響極小。**建議初版將其排除於設定之外**（走預設非雜訊），待基準集產出後再依真值決定。

## 實體二：雜訊分級（推導，不落地）

在 Worker 回應 week-detail 時對每篇文章計算：

```
entry    = config.sources[article.source]          // 完全相等比對
multiple = entry ? entry.multiple : null
noisy    = entry != null && entry.multiple < config.threshold
```

**性質**：

- 純函式，無副作用，無 I/O。輸入為文章的既有 `source` 欄位與設定物件。
- 不寫回資料庫，不快取。每次請求重算——成本為一次 map 查表。
- 設定變更後，**所有週次**（含最早的 W20）於下次請求即反映新值（FR-001b）。

## 實體三：使用者收起清單（瀏覽器端）

**存放位置**：瀏覽器持久化儲存，沿用列表既有逐條「標記過時」（`dismissArticle` / `applyDismissed`）所使用的同一機制與同一儲存區，但**獨立的鍵**，避免互相覆寫（FR-015）。

**形狀**：收起的收集來源名稱集合。

**規則**：

- 單位為收集來源（feed），非發稿媒體（FR-012 / FR-012a）。
- 跨週次、跨造訪保留（FR-013）。
- 與自動降級重疊時，使用者的收起優先——該來源完全不出現，不另外顯示降級提示行。取消收起後回復受自動降級管轄。
- 全部收起時顯示空狀態與一鍵還原（FR-014）。

## 狀態轉換：一篇文章的三種呈現態

```
                 使用者已收起該來源？
                    ├── 是 → [隱藏]  （完全不出現，可由還原操作回復）
                    └── 否 → noisy？
                              ├── 是 → [收合]（計入分組的降級計數，可點擊提示行就地展開）
                              └── 否 → [正常]（若同時具備高信號則額外突顯）
```

展開降級列為一次性檢視，不持久化（FR-008b）；分組收合時其內的降級提示行一併隱藏（FR-011a）。
