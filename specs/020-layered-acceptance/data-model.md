# Data Model: 分層驗收（spec 020）

這個功能不加資料表、不改 schema。下面是它引入的概念與各自的狀態。

## 執行模式

| 值 | 寫入 | LLM | 誰會用 |
|---|---|---|---|
| 正式（預設） | 照常 | 照常 | 排程的週報與每日執行、手動觸發的 `weekly.yml` |
| 不發布第一級 | 0 筆 | 0 次 | 不發布的 workflow |
| 不發布第二級 | 0 筆 | 照常呼叫 | 不發布的 workflow |

- 一次執行從頭到尾只有一個模式，不在中途切換。
- 沒設就是正式；不認得的值直接失敗（`contracts/dry-run.md`）。

## 片

| 欄位 | 說明 |
|---|---|
| 驗收範圍 | 九類之一：功能本身、必要的輸入、輸出、回收檢驗、修正、跨次執行的狀態、排程與串接、資源、觀測（觀測不是驗收條件） |
| 驗法 | 單元測試、不發布的執行（第一級或第二級）、重播、讀每日的紀錄、讀某一次實跑 |
| 要不要等實跑 | 只有其他驗法都驗不到時才是「要」，並寫明為什麼 |
| PR | 一片一個 |
| 結果 | 寫在那個 PR 的內文 |

狀態：規劃 → PR 開出 → 驗收通過 → merge。讀回那一片多一段：merge（紀錄的 PR）之前要等到那一次實跑。

## BACKLOG 列與片的關係

- 一個改動原本的那一列：在最後一個上線前驗得完的片的 PR 移出。
- 還有上線後的讀回時：同一個 PR 另開一列記讀回；那一列在讀回的 PR 移出。
- 讀回那一列的提醒：日期宣告（bare `GUB-20261114-gw7`）做好之前，寫進 `routines/weekly-verify/FOCUS.md`。

## 不發布執行的產物

見 `contracts/dry-run.md`「產物」。產物是檔案，不進資料庫；保留多久跟著執行環境對產物的設定走。
