# Contract: 不發布的週報執行

讀者是觸發它的維護者、讀它紀錄的人與 routine。行為是已定的（spec FR-001～FR-010、research D1～D5）；名字在 2026-11-15 `/speckit-tasks` 那一輪定案（spec 的 Clarifications）。
還是提案的只有三樣，下面各自標了：固定行的文字、產物目錄裡的檔名、傳產物路徑的兩個環境變數名。片 1 的測試鎖住的就是定案的版本。

## 入口

- 一個只能手動觸發的 workflow：`.github/workflows/weekly-dry-run.yml`，沒有排程。
- 一個必填的輸入 `level`：
  - `dry-input`（第一級）：收集、過濾、充實、選出入選；不呼叫生成式 LLM。交通過濾階段的 embedding 去重照常呼叫，它是入選的一部分。
  - `dry-full`（第二級）：第一級的全部，加分析、對每份報告跑一次 `check_report()`、術語收錄；不寫入、不發布。
- 一個必填的輸入 `category`（`traffic`、`ffxiv`，沒有預設值；提案，`GNS-20261013-4g9` 的「拆 workflow 的契約」，2026-11-17）：一次只跑一類，
  跟兩支正式的週報相同；交通分析那一步只在 `traffic` 跑，術語收錄只在 `ffxiv` 的第二級跑。空值與這兩個以外的值在任何程式步驟之前擋下。
- 可以選任一個分支執行；跑的是那個分支的程式。
- 跟 `weekly-traffic.yml`、`weekly-ffxiv.yml` 共用的準備步驟（寫設定檔、裝 Python、裝相依）逐步相同，程式步驟的 env 鍵也相同，由 `tests/unit/test_workflow_parity.py` 守。
- 沒有部署步驟，也沒有「驗證本週資料可由資料庫讀取」那一步（它驗的是剛寫進去的資料）。
- 開頭與結尾各跑一次 `scripts/dry_run_counts.py`，比對「不變的東西」那五個計數；不同就讓 job 失敗。

## 執行模式

- 程式從環境變數 `GARYU_RUN_MODE` 讀模式，值就是 `level` 的值：
  - 沒設：正式模式。正式排程的 workflow 不設這個變數，行為跟加入這個功能之前相同。
  - `dry-input`、`dry-full`：不發布的第一級、第二級。
  - 其他任何值：直接失敗、不往下跑。不退回正式模式的理由：拼錯一個字不能變成一次正式寫入。
- 每個寫入函式自己檢查模式。不發布時不呼叫資料庫，印一行，回傳 0。

## 執行紀錄裡的固定行

這幾行有讀者（維護者、之後的 routine），格式用測試鎖住。文字是提案：

| 什麼時候 | 行 |
|---|---|
| 每支程式開頭 | `[不發布] 第一級：只到入選，不呼叫生成式 LLM` 或 `[不發布] 第二級：呼叫 LLM，不寫入、不發布` |
| 每一次被略過的寫入 | `[不發布] 略過 <寫入函式的名字>：<N> 筆`；`expire_buffer_articles` 不查資料庫就不知道筆數，印 `[不發布] 略過 expire_buffer_articles：沒有查資料庫，筆數未知` |
| 第一級停下的地方 | `[不發布] 第一級在 <階段> 之前停下` |
| 交通分析疊上這次收集的清單 | `[不發布] 分析的輸入：buffer <N> 篇，加上這次收集的 <M> 篇（其中 <K> 篇 buffer 裡已經有）` |
| 每支程式結束 | `[不發布] 生成式 LLM 呼叫 <N> 次，embedding 呼叫 <M> 次`（第一級的 N 是 0；次數算送出的請求，重試也算） |
| 術語收錄 | `[不發布] 術語收錄：會寫入 <N> 條，沒有寫入`，後面逐條列出 |

正式模式下這些行都不出現。

## 產物

三個產物；每個檔的頂層帶一個 `run_mode` 欄位（`dry-input` 或 `dry-full`）寫明來自哪一級。目錄裡的檔名與兩個路徑變數（`TRAFFIC_POOL_DIR`、`ANALYSIS_OUTPUT_DIR`，比照現有的 `FFXIV_POOL_DUMP`）是提案。
片 1 到目前寫出的檔：`TRAFFIC_POOL_DIR/collected.json`（逐來源的漏斗、正式執行會寫進 buffer 的那些列）、`ANALYSIS_OUTPUT_DIR/ffxiv_articles.json`（FFXIV 逐篇分析全文）。
路徑變數沒設或寫不進去時各印一行（例：`交通候選清單：未設 TRAFFIC_POOL_DIR，不寫檔`），不失敗、不靜靜略過。站台檔不產生時印 `[不發布] 略過 站台檔 <目錄>：<N> 筆`。

| 產物 | 哪一級 | 內容 |
|---|---|---|
| `ffxiv-pool`（沿用現有的） | 兩級 | 整個候選池與入選的篇數。正式模式的格式不變 |
| `traffic-pool` | 兩級 | 每個來源的收集數、過濾後數與過濾充實後的清單；選出的熱點 bucket、彙整池的篇數與來源分布；前後兩份計數 |
| `analysis-output` | 第二級 | 每一份三軸報告、彙整報告、FFXIV 逐篇分析的全文；每份報告 `check_report()` 的命中（未經逐條判定）；術語收錄會寫入的條目 |

產物之後可以拿來重播。這個 repo 是公開的，產物外人讀得到（已定可以）。

## 不變的東西

觸發前後，下面五個計數相同（SC-001）：報告數、buffer 筆數、彙整池未分析筆數、兩個站的最後部署時間、術語庫的條目數。
計數抓不到既有的列被改寫；那一半由 `tests/unit/test_storage_dry_run.py` 與 `tests/unit/test_auto_kb_dry_run.py` 守。
不發布的執行成功結束不會連帶觸發 `auto-kb.yml`（它只認週報 workflow 的名字）。
