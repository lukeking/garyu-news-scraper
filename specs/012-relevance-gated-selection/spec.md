# Feature Specification: 相關性選材閘（Relevance-Gated Selection）

**Feature Branch**: `012-relevance-gated-selection`
**Created**: 2026-08-05
**Status**: Draft
**Input**: User description: "機車事故選材離題"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 機車事故熱點只出現真正的事故／道安內容 (Priority: P1)

讀者在每週交通週報掃到「機車事故」熱點時，看到的應是真正的交通事故／道安事件，
而不是只因標題出現「機車」二字就被選入的竊盜、外遇求償、潑糞報復、毒駕羈押等刑案社會新聞。

**Why this priority**: 這是本功能的核心價值，也是損害最大的一處——08-03 實測「機車事故·中時」
10 篇選材約 5 篇離題，且既有的標題形式品質分數還把毒駕羈押刑案排到全桶第一（0.405）。
離題內容直接印進已發布的報告，傷害閱讀品質。

**Independent Test**: 取某一週的「機車事故」桶，對每篇候選文章做人工相關性標記（事故／非事故），
驗證發布出的文章離題比例低於門檻。只做這一條就已交付「事故熱點名副其實」的價值。

**Acceptance Scenarios**:

1. **Given** 一則標題含「機車」但內容為竊盜／毒駕羈押的刑案新聞, **When** 系統選材機車事故熱點, **Then** 該篇不得被選為代表該熱點發布。
2. **Given** 一則真正的機車事故新聞（撞擊／追撞／自撞／送醫／車禍）, **When** 系統選材, **Then** 該篇正常入選，不受相關性閘誤傷。
3. **Given** 桶內存在離題刑案，且其標題形式品質分數高於某真正事故新聞, **When** 排序與選材, **Then** 相關性優先於標題形式分數，離題高分篇不得擠掉正題篇。

---

### User Story 2 - 系統性離題來源不得整席佔據一個熱點 (Priority: P2)

一個系統性產出「含車種關鍵字但實為行銷稿」的來源（如車媒《地球黃金線》產出的銷量戰報／
油耗排名／市佔率／車輛規格報導），不得填滿某個熱點的整個發布名單。

**Why this priority**: 08-03「機車事故·金線」5 篇選材整席離題，一則事故都沒有——一個發布席次
被單一行銷來源完全浪費。這不是偶發雜訊，是一整類來源穩定打進事故桶；量級大（整席），
但比 US1 的病灶單純（可在來源層級辨識），故列 P2。

**Independent Test**: 對一週資料，確認車媒行銷文章不會構成任一熱點的多數／整席；
若某桶候選全數為此類，該熱點不發布。

**Acceptance Scenarios**:

1. **Given** 某熱點桶的候選全數為車媒行銷稿（銷量／油耗／市佔／規格）, **When** 選材, **Then** 該熱點不發布（寧缺勿濫）。
2. **Given** 一則來自車媒但確實報導真實事故的文章, **When** 選材, **Then** 不因來源類別被誤刪——來源層級的降權不得凌駕單篇的真實相關性。

---

### Edge Cases

- 桶內所有候選都離題 → 該熱點不發布（FR-003）。若因此某週發布的熱點數低於慣常 3 席，接受「較少但乾淨」。
- 邊界內容：肇事逃逸／公共危險致人受傷同時是「刑案」也是「事故」——傷亡型交通事件屬事故，單純竊盜不屬——相關性定義要能區分這兩者。
- 混合文章：一篇行銷稿順帶提到一則真實事故，或一篇事故報導夾帶車款資訊 → 如何歸屬。
- 來源類別誤傷：真正的事故報導剛好來自以行銷為主的來源 → 來源降權不得吃掉真實相關的單篇（US2 場景 2）。
- 正題稀缺週：離題移除後桶變薄，須確認既有的三種降級顯示狀態與新穎度閘不受破壞。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 在一篇文章被選入某熱點發布之前，判定它對該熱點主題是否**相關**（實際主題相符），而不只是標題是否含該主題關鍵字。
- **FR-002**: 一篇「含主題關鍵字但實際主題落在該主題之外」的文章（例如僅提及「機車」的刑案社會新聞，或產品行銷稿）MUST NOT 被選為該熱點的代表文章。
- **FR-003**: 當某熱點桶的候選集整體離題時，系統 MUST NOT 發布該熱點——沒有熱點勝過一個名不副實的熱點。
- **FR-004**: 系統 MUST 阻止「系統性產出含關鍵字但離題內容的來源」（如車媒行銷）填滿某熱點的發布名單。
- **FR-005**: 相關性判定 MUST NOT 僅依賴既有的標題形式品質分數（該分數量的是標題形式，非主題相關性，且實測會把離題刑案排到全桶第一）。
- **FR-006**: 相關性判定 MUST NOT 增加選材階段的每次執行成本或外部服務呼叫量（選材階段目前不呼叫任何外部 AI；本功能須維持此成本輪廓——憲章 IV Free Tier Discipline）。
- **FR-007**: 來源層級的離題降權 MUST NOT 凌駕單篇的真實相關性——確有事故報導的文章即使來自行銷型來源也應保留。
- **FR-008**: 本功能 MUST NOT 破壞既有行為：跨週新穎度閘（novelty／去重）、每次至多 3 席熱點、分類指派、以及既有的降級顯示狀態。

### Key Entities

- **熱點桶（Topic bucket）**：一組被歸為談論同一主題的文章（例如「機車事故」）。含候選文章，其中一子集被選中並發布。
- **文章（Article）**：具標題、來源、（og）摘要。目前的選材依「標題 token 命中 + 標題形式品質分數」。
- **來源類別（Source class）**：具特徵性內容型態的一類來源（例如系統性產出行銷稿的車媒）。
- **主題相關性（Topic relevance）**：一篇文章的**實際主題**是否符合桶的主題——與「關鍵字是否出現」及「標題形式品質」皆為不同維度。

## Success Criteria *(mandatory)*

**量測前提**：需要一份**人工相關性標記的基準集**（取樣數週，對每篇候選標記 on／off-topic）。
承 011 的教訓，**禁止以主觀印象填**；硬門檻只接受實測（見 Assumptions）。基準取自 08-03
實測：3 個發布熱點有 2 個實質離題；桶內離題比例「機車事故·中時」約 50%、「機車事故·金線」100%。

**階梯**（Gate 設在最寬鬆那階，每階錨定一個真實 08-03 場景）：

- **SC-001（L0 / Gate）**：任一發布熱點的名單不再出現「多數（>50%）離題」。錨定：金線那份 100% 行銷的整席不會發布。
- **SC-002（L1）**：任一發布熱點內，離題文章比例 ≤ 20%。錨定：中時那份約 50% 刑案混雜被清到以事故為主。
- **SC-003（L2 / 理想）**：取樣 N 週，發布熱點內離題文章為 0。
- **SC-004（不回歸）**：真正 on-topic 文章的發布數量不因本功能下降——移除的是離題，不是正題。

## Assumptions

- 選材／分群目前為零 AI 的確定性運算；本功能維持此成本輪廓（憲章 IV）。相關性以便宜／確定性手段判定，不新增選材階段的外部 AI 呼叫；真正難判者留待 /plan 決定。
- 發布摘要模型已能辨識離題（金線整席它主動標「查無事故」），但它在**選材之後**執行，救不了已被選進來的東西——故修正點在選材，不是換模型。
- 相關性以文章**實際主題**為準，量測需人工標記基準集；主觀印象不算量測（承 011 SC 未量測之戒）。
- 「寧缺勿濫」：若離題移除使某週熱點數低於 3，接受較少但乾淨的發布。
- 候選機制（事故 token 白名單／刑案·市場 token 黑名單／行銷來源降權）是 /plan 的實作選項，非本 spec 固定。

## Out of Scope（含待決策項）

- **政策 digest 的單篇離題（BACKLOG #7）**：食安政治新聞經 道安會報 feed 進政策彙整（每週約 1/25），與本題同根（選材吃 token 不量相關性），機制可共用同一個相關性閘。**本 spec 決定不納入**（使用者 2026-08-05 定：只做機車事故 traffic 側）——#7 留作獨立後續；若本題的相關性閘機制通用，日後可沿用（BACKLOG #7 保留）。
- 更換發布摘要模型，或對已選文章做 LLM 相關性覆核——被成本線排除（FR-006）。
- 圖片覆蓋率、buffer 列模型（BACKLOG #5）等無關項。

## Dependencies

- 既有選材／分群／新穎度管線（specs 009、010、011）。
- 一份人工相關性標記基準集（如 011 的手動基準需求）以量測 Success Criteria。
