# garyu-news-scraper Backlog

本 repo 還沒做完的工作：spec 候選、待查的缺陷、留了重開條件的決定。開 spec 時才配 `NNN-` 編號。

**這份檔案是本 repo 的狀態記錄**——一個項目 ship 之後要從中移出的就是下面那張表
（見 `~/.agents/instructions/rules/spec-closeout.md`）。**`HANDOFF.md` 不是**：它只在 handoff 當下取樣、
之後不會重新取樣，所以它與現況不符是設計不是缺陷，closeout 不要去更新它。
**這裡不放**：不是待辦的常設提醒與領域知識（在 `docs/standing-cautions.md`）、進行中工作的狀態
（在 spec 與 PR）。

**id 慣例**：`GNS-YYYYMMDD-xxx`——專案代碼、開條目那天、3 個 Crockford base32 小寫亂數字元。
格式、代碼登記與為什麼不用連號：`~/.agents/templates/BACKLOG.md` 與
`~/.agents/instructions/rules/output-conventions.md`「序列編號」一節。**id 由腳本產生，不要自己編**：

```bash
python3 ~/.agents/bin/backlog.py add specs/BACKLOG.md <項目> <觸發點> <完成標準>   # 印出新 id
python3 ~/.agents/bin/backlog.py remove specs/BACKLOG.md <id>                     # 移出整列與它的小節
```

寫完讀一次 diff。找 id 用 `grep -w`。離場的條目用 `git log -S "<id>" -p -- specs/BACKLOG.md` 整列撈回來。

後綴長度：3

**舊稱對照**：2026-09-21 之前的 commit、PR、memory 與程式註解裡寫的「BACKLOG #N」＝ `GNS-0NN`
（例如 `#13` ＝ `GNS-013`）；2026-09-21～10-05 發的 `GNS-NNN` 照留，不改號。本檔內 `#` 後面接的數字
除了 `OQ#N`（open question）之外一律是 PR。2026-10-05 起新條目用 `GNS-YYYYMMDD-xxx`。

**表裡只有還沒做完的條目，沒有狀態欄。** 在表裡＝還要做；做完就在完成它的那個 PR 裡整列移出
（它專屬的小節一起移出），PR 內文的 `Backlog:` 列出移出的 id，實際做法寫進那個 PR 的內文。
**不加 `DONE` 狀態、不留到下一次**——為什麼，見 `~/.agents/templates/BACKLOG.md`「完成就移出」。
各節**不寫狀態**：要知道一個項目還在不在，永遠只看表。
**整份只有一張 id 表**，列與列之間不能有空行（空行會結束 Markdown 表，腳本會拒絕這種檔案）。
