本 repo 還沒做完的工作：spec 候選、待查的缺陷、留了重開條件的決定。開 spec 時才配 `NNN-` 編號。

**這份檔案是本 repo 的狀態記錄**——一個項目 ship 之後要從中移出的就是下面那張表
（見 `~/.agents/instructions/rules/spec-closeout.md`）。**`HANDOFF.md` 不是**：它只在 handoff 當下取樣、
之後不會重新取樣，所以它與現況不符是設計不是缺陷，closeout 不要去更新它。
**這裡不放**：不是待辦的常設提醒與領域知識（在 `docs/standing-cautions.md`）、進行中工作的狀態
（在 spec 與 PR）。

**id 慣例**：`GNS-YYYYMMDD-xxx`——專案代碼、開條目那天、3 個 Crockford base32 小寫亂數字元。
格式、代碼登記與為什麼不用連號：`~/.agents/templates/BACKLOG.md` 與
`~/.agents/instructions/rules/output-conventions.md`「序列編號」一節。**id 由腳本產生，不要自己編**：

```bash
python3 ~/.agents/bin/backlog.py add specs/BACKLOG.md <項目> <觸發點> <完成標準>   # 印出新 id
python3 ~/.agents/bin/backlog.py remove specs/BACKLOG.md <id>                     # 移出整列與它的小節
```

寫完讀一次 diff。找 id 用 `grep -w`。離場的條目用 `git log -S "<id>" -p -- specs/BACKLOG.md` 整列撈回來。

後綴長度：3

**舊稱對照**：2026-09-21 之前的 commit、PR、memory 與程式註解裡寫的「BACKLOG #N」＝ `GNS-0NN`
（例如 `#13` ＝ `GNS-013`）；2026-09-21～10-05 發的 `GNS-NNN` 照留，不改號。本檔內 `#` 後面接的數字
除了 `OQ#N`（open question）之外一律是 PR。2026-10-05 起新條目用 `GNS-YYYYMMDD-xxx`。

**表裡只有還沒做完的條目，沒有狀態欄。** 在表裡＝還要做；做完就在完成它的那個 PR 裡整列移出

**📊 校準起點（2026-08-17，spec 013 T018 的副產物）——⚠️ 2026-08-31 已知其分類有誤，見本節末**：匯流後第一份 prod 週報

⚠️ n=22、單週單次——當作**起點**不是結論，第二份（08-24）到手前不要據此定閾值。

**問題**：`initial_quality_score` 量的是**標題的形式品質**（長度、資訊密度等），
不是**主題相關性**。於是一則寫得好的離題新聞會排在一則平實的正題新聞之上，
而 digest 選材吃的是分數。

**07-27 實測**（`道安政策 · 彙整`，池 49／選 25）：

```
score=0.1986  選中=True   林延鳳踢爆「蔣萬安食安會報缺席11次」…    ← 食安政治新聞
score=0.183   選中=False  提升學生用路安全意識 大專校院交通安全種子師資培訓  ← 道安正題
```

那篇食安新聞來自 `Google News 道安會報` feed，經 source_default 進池
（標題無分類關鍵字），再靠分數擠掉正題文章進入發布的報告。

**已經在運作的防線，不要重複造**：低分垃圾標題**已被擋住**，不必再處理——

```
score=0.165   選中=False  友善列印 - 新竹市政府交通處
score=0.1842  選中=False  AUTO ONLINE 汽車線上 - AUTO ONLINE 汽車線上
```

`quality_floor` 0.18 擋掉第一則（也是 `pool=49 effective=46` 那 3 篇之一），
25 篇的截斷擋掉第二則。**缺的不是分數門檻，是相關性判斷**——這兩件事目前由
同一個數字承擔，而它只做得到前者。

**與 PR #75 的關係**：#75 移除 `處罰條例` 的 source_default，處理的是
**來源層級**全數離題的情形（4/4）。本項是剩下的**單篇層級**漏網——來源整體精確度
80–95%，但那 5–20% 仍會靠分數進報告。同一個現象的兩個層級，#75 解掉了便宜的那半。

**候選解法（未評估，開 spec 時再比）**：
- 分類關鍵字加權：進了政策桶但標題完全沒有政策 token 的文章降權
- digest 選材時做一次輕量相關性判斷（有成本，違反「每日零 AI」以外的成本線要先想清楚）
- 縮小 feed query（例如 `道安會報` 加限定詞避開「食安會報」「公安會報」）——最便宜，
  但治標，且會連帶降低召回

**量級提醒**：每週約 1/25 篇。**不要為了這個把選材管線複雜化**——先確認它會不會長大。

## GNS-009 桶分數門檻殺乾淨小桶（門檻是對「未過濾的桶」校準的）

**提出**: 2026-08-08，spec 012 量測 SC-004 時發現（**實測副產物，不是推測**）
**優先度**: 建議順序 GNS-009——不擋任何人，但它是**三個既有問題的共同結構根因**
**範圍**: 012 的 T016 明文把它排除在 012 範圍外，要另開 spec。

**問題**：`min_threshold` 是對**未經過濾的桶**校準的。相關性閘移除離題文章後，桶分數必然下降
（`score = Σquality × log(來源數+1) × log(天數+1)`，**三個因子同時縮小**），於是一個**乾淨但小**
的桶會跌破門檻、整桶不發布——連它的 on-topic 文章一起帶走。

**實測（spec 012，實測）**：`機車事故 · 中央社` 過濾後剩 2 篇乾淨事故文、分數 0.63，
`min_threshold: 1.5` → 不發布。012 的 4 筆 on-topic 損失裡有 **3 筆是這個原因**（另 1 筆才是規則漏抓）。
這正是 SC-004 卡在 L0 上不去 L1 的唯一原因——**不是 token 沒調好**。

**與 spec 010 是同一個結構問題**：010 的 道安政策 singleton 天花板 0.22 vs 門檻 1.0，
也是「內容沒問題，但量體撐不起分數」。010 用 digest（聚合）繞過去，沒有解掉門檻本身。

**已量測否決的兩條捷徑（別再走一次）**：

| 方案 | 實測結果 |
|---|---|
| (a) 全面降 `category_min_threshold` | 掃到 ≤1.0 時離題比例**爆回 100%**——髒桶跟著一起復活 |
| (b) 桶分數改用「過濾前」計算 | 離題 **100%**、SC-001 直接失守——該死的爛桶不再死 |

**核心難點**：同一個門檻同時殺乾淨小桶與髒桶，而**用分數分不開它們**——因為分數不含相關性資訊，
這恰好又是 GNS-007／機車事故那條線的同一個病根在另一個位置復發。需要比「降門檻」更聰明的東西
（例如把門檻改成對過濾後的桶重新校準、或讓乾淨度進入分數、或對小而乾淨的桶走 010 式聚合）。
**未評估，開 spec 時再比。**

### 界線

與 GNS-010（機車事故 require 表漏抓真事故，PR #97）：GNS-010 是「真事故根本沒進桶」，在閘；本項是「乾淨小桶跌破門檻」，在門檻。
兩者都會吃掉 on-topic 文章但位置不同——修任何一個都不會修到另一個。

**`gh variable set` 的真實行為（2026-08-10 binary 模式實測，更正前一版的說法）**：

| | bytes | CRLF 行 |
|---|---|---|
| 本機（當時，CRLF） | 5400 | 105 |

**PR #88 的 commit message 與本節前一版寫「−105、prod 已正規化為 LF」，那是錯的**——

**結論不變但理由換了**：仍然用 YAML parse 比物件——不是因為偏移量不可預測
（它其實可預測），而是因為位元組相等**對「設定是否正確」這個問題根本不是必要條件**，
而且任何一端的編碼／EOL／尾端空白變動都會讓它假失敗。

**同日附帶處理**：`config/pipeline_config.yml` 是本 repo **唯一**還帶 CRLF 的檔（105/105 行），

該規則只在 git 自己 checkout／add 時套用，而 git 永不讀寫被忽略的檔。
其餘 gitignored config 是 LF 屬於**出身運氣**（多半複製自被追蹤的 `.example`），不是有東西在守。

### ⚠️ 解法換過：不是「補來源」（2026-08-10，spec 013／PR #86）

**「補來源」的前提查證後不成立。** 07-20 加的六個政策來源自那時起**產出 179 篇**——
它們並非沒產出。但只有 `交通安全教育` 進得了政策池（88/91＝97%），原因不是它產量大：

- 它在 `source_defaults` 對映到 `道安政策`，**且標題不帶分類 token** → `assign_category`
  判為 `uncategorised` → fallback 生效 → 整批進池。
- 其餘來源的標題**帶了 taxonomy token**（`禁行`→路權政策、`行人`→行人事故、`路口`→路口安全）
  → 分類直接命中 → **`source_defaults` 這條 fallback 永遠不會觸發**（它只在 `uncategorised` 時生效）。

而 `category_digest` 只設了 `道安政策`，`路權政策`／`科技執法`／`交通工程` 遠低於熱點門檻
`min_threshold: 1.5`，**永遠不會發布**——內容收進來、存起來、丟掉。

**所以政策池不是缺來源，是政策內容被分類法切碎在門檻之下**（與 spec 010、BACKLOG GNS-009
同一個結構）。兄弟類別的來源**比政策池本身分散一倍**：distinct 8／最大來源 24%，
而政策池是 distinct 4／最大 73%。

**解法＝digest 選材時匯流兄弟類別**（`include_categories`，設定驅動、不動分類法）。

| 抽掉最大 feed 後 vs 門檻 10 | 9 → 不 TRIGGER | **18 → 仍 TRIGGER** |

**零新增來源。** 詳見 `specs/013-policy-digest-pool-merge/`。

**「補來源」沒有消失，只是換了位置與理由。** 013 實測 SC-001 L2（最大來源 ≤50%）未達成——
`交通安全教育` 那 28 篇本身就佔匯流後 46 篇的 60.9%，要再壓低**需要更多內容**，

## GNS-20261005-nwn `embed_dedup` 比對窗怎麼改（OQ#2）

**出處**：GNS-007（政策 digest 離題雜訊）的「重複那半」，2026-10-05 從 GNS-007 節搬出來立成一列。

⚠️ **2026-09-05 量完，這一條原本把嫌犯指錯了**：不是 `embed_dedup` 的 **threshold**，
是它的**比對窗**。儀器＝`scripts/measure_embed_dedup_gap.py`（唯讀，可重跑）。
全語料 1252 篇有嵌入，餘弦 **≥ 0.88 卻仍並存在庫裡**的有 **1685 對**：

門檻本身沒問題：`顏蔚慈交通白皮書` 那 7 篇的 **21 對全部 ≥ 0.88**，`駕艙機車` 有一對

**未決定的是要不要把窗放寬**（見 GNS-007 節 reopen 條件 3 的註記），因為跨週相似有兩種：
同一則新聞的改寫（該去重）與同一事件的後續進展（不該去重），**餘弦分不出這兩者**。

當時文章沒有向量，daily 去重比不到，回填後才浮出來（分週分布 實測；逐對因果 推論，回填沒記 id）。

|---|---|---|
| 3189 | 89.1% | 跨週 |

| 286 | 8.0% | 同週且在比對窗內 |

⚠️ **儀器的歸因修過一次**：舊版用「現在」的已分析旗標，把兩篇都在週二～週日進庫、下週一才一起被消耗的對
也歸成比對範圍外。改成看**後進那篇進庫當下**先進那篇在不在窗內：同週只有週一的週報會消耗，所以先進那篇
得是週一那批、且已被分析（推論：沒有消耗時間可查，假設週一那批當天就被消耗）。舊歸因今天是 150／241。

比對窗內的去重在故障修好後有在作用，缺口在窗的邊界。

**digest 裡同題佔兩格的成因**（實測）：不是沒有向量，也不是餘弦 < 0.88（那幾對在 0.957～0.967），
是比對窗在週一的兩個缺口：
1. 週一週報 run 收的那批只跟「本週 `week_id`、未分析」比，看不到上週 daily 收進來、還沒被消耗的列；
   接著選材把兩週一起消耗，同一份 digest 就佔兩格（09-21 id 3950↔4138、09-28 4229↔4401、10-05 4500↔4725）。
2. 週一那批當天被消耗，同週之後 daily 收到的重複比不到它（3842↔3950、4138↔4229、4401↔4500、4134↔4322）。

「中壢警 125 件」（09-11 發布）W37～W41 連續五週、9 篇進庫：來源 `Google News 交通安全教育` 的
`lookback_days` 是 30，舊文章換個轉載網址一再回來。

| 餘弦 | 發布差 < 1 天 | 1–3 天 | 3–7 天 | 7–14 天 | 14 天+ | 合計 |
|---|---|---|---|---|---|---|

| 0.92–0.96 | **256** | 51 | 48 | 33 | 102 | 500 |
| 0.96–1.00 | **293** | 17 | 4 | 12 | 26 | 353 |

發布差 < 1 天的 868 對：76% 至少一篇來自帶 `lookback_days` 的來源，58% 後進那篇是週一進庫；
後進那篇「進庫 − 發布」中位數 11.8 天、P90 26.8、最大 29.8——卡在 30 天視窗內。
抽樣（每個餘弦區間 6 對、`random.Random(20261005)`，判斷）：看起來是同一則新聞的比例
≥0.96 12/12、0.94–0.96 約 5/6、0.92–0.94 約 3/6、0.90–0.92 約 2～3/6、0.88–0.90 0/6。
低段多是**同類型、不同事件**（每月的道安會報、不同的待轉區事故）——跨週相似其實有三種，不是兩種；
「餘弦分不出改寫與後續」只在中段成立。發布時間差那張表與抽樣是一次性腳本（沒進 repo）：
取跨週 ≥0.88 的對，按兩篇 `published` 的差分組。

- 跨週只擋「發布差 < 1 天且餘弦高」的——瞄準舊文章重新進來的那 868 對，放過後續進展與同類事件。
- 來源端：30 天視窗的來源不再收已經見過的舊文章。

## 這份清單自己的訊號

沒有人更新這份清單時會發生什麼——大多數條目什麼都不會發生：

- **有執行者的只有 GNS-008**：週驗收 routine（`routines/weekly-verify/`）每週一讀週報 log 判定重開條件，
  結果寫進 Linear 本週 issue。routine 沒跑（沒有自動重試）或 `FOCUS.md` 沒滾動時，那一週沒有人判。
- **其他條目的觸發點沒有東西在看**：它們靠「動到相關檔案的人先讀到這張表」。沒有人讀，條目就躺著，
  而躺著從外面看不出來。`GNS-20261005-24s`（正文抓取）的訊號（daily log 的 `GN 充實：…（失敗網域：…）`）目前也沒有 routine 在讀。
- **移出沒有機械檢查**：本 repo 的 PR 沒有 `Backlog:` 行的檢查（`check_backlog_pr.py` 只接在 bare-repo）。
  做完卻沒移出的列，只有下一個讀表的人會發現。
