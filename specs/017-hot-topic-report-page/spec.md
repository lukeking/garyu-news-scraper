# Feature Specification: 熱點報告與新文章拆成兩條流

**Feature Branch**: `017-hot-topic-report-page`  
**Created**: 2026-11-03  
**Status**: Draft  
**Input**: BACKLOG `GNS-20261031-005`（交通頁的週報熱點掛在產生那週，內容卻是之前累積的文章，跟同頁下方的文章對不上）。
Luke 2026-10-31 提出；2026-11-02 選「只補標示」開了 spec 016；2026-11-03 看過 016 的簽核畫面後放棄 016（PR `#197` 已關），
改成報告與文章分成兩條流。

## 背景：為什麼要拆

Luke 10-31 的原話：「traffic daily buffer 和週報產生週期跟 UI 呈現已經脫鉤，我打開介面看到的週報熱點分析是從上禮拜的
buffer 來的，但下方的 daily buffer 卻都是這週的。」

Luke 11-03 的原話（看過 016 的簽核畫面之後）：「因為週報永遠都是拿前面七天累積的文章(不精確但方向是這樣)，所以他產出來的時候
不管放哪裡都會有問題，跟舊的放一起，一出生就過期。跟新的放一起，buffer 內容跟熱點天然脫鉤。我覺得應該是週報獨立自己的頁面，
有必要的時候讓熱點單向索引 buffer 呈現，避免頻繁來回切換頁面，buffer 頁面則不需要知道自己被哪一則熱點引用。」

- 現況：交通頁每個週次頁面，上方是掛在這一週的熱點報告，下方是這一週收集的文章，兩者共用同一個週次導覽。
- 錯位是設計本身帶來的：選題靠跨天累積分數（報告資料帶 `cumulative_score`、`distinct_days`），buffer 留到 8 週，
  讓單週量不夠的主題累積到門檻（spec 010 的彙整）。所以報告永遠對不上單一一週。
- 2026-11-02 prod 唯讀量測（55 份報告，不含一筆測試殘留；全文在分支 `016-hot-topic-source-range` 的 `spec.md` 背景與 `research.md`）：
  52 份的來源橫跨不只一個收集週；「來源最多的那個收集週」34 份是上一週、2 份是報告掛的那週、19 份是 2～7 週前；
  彙整型報告的來源發布日期往回涵蓋近一個月。
- 016 的做法是在卡片上寫出來源的發布日期區間；簽核畫面顯示它只防誤讀，不同時間帶的兩個區塊仍在同一個頁面上。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 熱點報告與新文章是兩條各自的流 (Priority: P1)

讀者打開交通頁，看到的是兩條分開的流：熱點報告依週報的批次排，新文章依收集週次排，兩條各有自己的導覽。手機上一次看一條、
可以切換；桌機夠寬時兩條左右並排。不論哪一種排法，報告都不再掛在某個週次的文章底下。

**Why this priority**: 這就是 `GNS-20261031-005` 的核心——不同時間帶的內容不再共用同一個時間軸。

**Independent Test**: 在手機寬度打開交通頁，切換兩條流，各自的導覽只動自己那一條；在桌機寬度打開，兩條並排、各自捲動與導覽；
新文章那一條的任何一個週次都沒有熱點報告，文章列也沒有被報告引用的標示。

**Acceptance Scenarios**:

1. **Given** 手機寬度（412 px），**When** 讀者打開交通頁，**Then** 一次只顯示一條流，有明顯的方式切到另一條。
2. **Given** 熱點那一條，**When** 讀者看它，**Then** 預設是最新一批報告（例：2026-11-02 那一週的「機車事故 · 中時」與「道安政策 · 彙整」），
   每份寫出它是哪一次週報，可以往回看更早的每一批。
3. **Given** 新文章那一條，**When** 讀者切換週次，**Then** 只有文章跟著換，熱點那一條不動，反之亦然。
4. **Given** 桌機寬度且放得下兩欄，**When** 讀者打開交通頁，**Then** 兩條左右並排，各自有標頭與導覽。
5. **Given** 桌機寬度但放不下兩欄，**When** 讀者打開交通頁，**Then** 照手機的排法顯示。
6. **Given** 新文章那一條裡一篇曾被某份報告引用的文章，**When** 讀者看文章列，**Then** 它和其他文章一樣，沒有 ★、沒有因被引用而來的加強樣式。

---

### User Story 2 - 一眼看出哪一條有新的 (Priority: P1)

讀者打開交通頁時，兩條流各自標出「上次看過之後有沒有新的」：熱點有沒有新報告、新文章多了幾篇。讀者照標記決定先看哪一條。

**Why this priority**: 舊版一路往下捲就全看得到，不用選；拆成兩條之後多了「先看哪邊」的選擇，標記就是把這個選擇成本降回來的東西。

**Independent Test**: 看過兩條流之後，等新文章進來（或模擬一份新報告），再打開交通頁，對應那一條出現標記、數字正確；看過那一條之後標記消失。

**Acceptance Scenarios**:

1. **Given** 讀者上次看過新文章之後又收進 23 篇，**When** 打開交通頁，**Then** 新文章那一條標出有 23 篇新的。
2. **Given** 讀者上次看過熱點之後產生了新的一批報告，**When** 打開交通頁，**Then** 熱點那一條標出有新報告。
3. **Given** 某一條有標記，**When** 讀者看過那一條（窄螢幕上切到它再切走，或下次打開），**Then** 那一條的標記消失，另一條的標記不受影響。
4. **Given** 第一次進來的讀者，**When** 打開交通頁，**Then** 不顯示一堆「全部都是新的」標記。
5. **Given** 讀者收起了某個來源，**When** 那個來源收進新文章，**Then** 新文章的篇數不算它們。

---

### User Story 3 - 打開時落在讀者要的那一條 (Priority: P2)

讀者打開交通頁時，落在上次離開時看的那一條；第一次進來落在熱點。齒輪設定可以改成固定開熱點或固定開新文章。

**Why this priority**: 手機上一次只看得到一條，打開時落在哪一條決定第一眼看到什麼；排在 US1、US2 之後，因為沒有它兩條流仍然成立。

**Independent Test**: 清掉站上的本機設定後打開 → 落在熱點；切到新文章、關掉再開 → 落在新文章；齒輪設成「熱點」之後，不論上次看哪一條都落在熱點。

**Acceptance Scenarios**:

1. **Given** 第一次進來，**When** 打開交通頁，**Then** 落在熱點。
2. **Given** 齒輪設定是「預設」且上次離開時在新文章，**When** 再打開，**Then** 落在新文章。
3. **Given** 齒輪設定是「熱點」（或「新文章」），**When** 打開，**Then** 一律落在那一條。
4. **Given** 一個舊格式的報告分享連結（`?week=…#topic-…`），**When** 打開，**Then** 正常進到交通頁、落在照上面規則決定的那一條，不出現錯誤或空白頁。
5. **Given** 改版後從報告卡片分享出去的連結，**When** 打開（不論齒輪設定、也不論之後又產生了新報告），**Then** 落在熱點那一條、
   切到那份報告所在的那一批，並定位到那份報告。

---

### User Story 4 - 在報告裡就看得到它引用的文章 (Priority: P3)

讀者讀一份報告時，想看某個焦點事件在講什麼，不必切到新文章那一條去找。引用是單向的：報告知道自己引用了哪些文章，文章不知道自己被哪份報告引用。

**Why this priority**: 拆成兩條之後，讀者可能為了看來源在兩條之間來回切；這條讓拆開不增加切換。沒有它拆開仍然成立，所以排最後。

**Independent Test**: 在熱點那一條讀一份報告與它的焦點事件，全程不需要切到新文章那一條。

**Acceptance Scenarios**:

1. **Given** 一份報告的某個焦點事件，**When** 讀者想看那篇的內容，**Then** 點一下那個焦點事件就地展開它的摘要與原文連結，不必切到新文章那一條。
2. **Given** 一個在資料裡找不到對應文章、或只存了連結的焦點事件，**When** 讀者看它，**Then** 至少看得到連結，沒有可展開的空摘要，頁面不壞。

---

### Edge Cases

- 舊的報告分享連結指到的週次沒有報告、或標題對不到：照 US3 的預設規則落地，不報錯。
- 新格式的報告分享連結指到的報告不存在（例如被刪掉）：照 US3 的預設規則落地，不報錯。
- 同一個標題每週都會出現（「道安政策 · 彙整」10-26、11-02 都有）：新格式的分享連結要同時帶批次與標題，不能只看標題。
- 「有新的」標記只記在讀者這台裝置：換一台裝置看，標記從那台自己的記錄算起。
- 讀者很久沒來（例如一個月）：8 週以內照實算出篇數，不因跨了好幾個週次而算錯或只算最新一週；基準早於 8 週時顯示「N+」，
  N 是 8 週內數到的篇數（每次打開的請求數要有上限，憲章原則 IV）。
- prod 有一份 2025-W02 的測試殘留報告（`酒駕-integration-test`）。現在沒有週次頁顯示它，但熱點那一條若列出全部報告就會出現；它不能出現。
- 報告清單載入失敗：熱點那一條顯示載入失敗的訊息；新文章那一條不受影響（它不需要報告清單）。
- 焦點事件在資料裡找不到（2026-11-02 量到 602 項有 3 項）或是舊格式只存連結（11 項）：顯示連結，不顯示空的摘要。
- FFXIV 頁面沒有熱點報告：不出現兩條流的切換、標記與齒輪設定，畫面照舊。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 交通頁 MUST 把熱點報告與新文章呈現成兩條流，各自有自己的導覽：熱點依產生的批次，新文章依收集週次。
  新文章那一條 MUST 不再顯示熱點報告。
- **FR-002**: 手機寬度 MUST 一次顯示一條流，並提供切換；寬度放得下兩欄時 MUST 左右並排，放不下時照手機的排法。
  「放得下」的寬度門檻在簽核畫面時以實測決定，寫回本 spec。
- **FR-003**: 熱點那一條 MUST 預設顯示最新一批報告，每份寫出它是哪一次週報（FR-011）；讀者 MUST 能瀏覽更早的每一批。
- **FR-004**: 兩條流 MUST 各自標出讀者上次看過之後的新內容：熱點標出有沒有新報告，新文章標出新文章的篇數；
  新文章的篇數 MUST 不含讀者收起的來源（與頁面上的統計一致，spec 011 US2：收起的來源「完全不出現」也包含篇數）。
  讀者看過那一條之後，那一條的標記 MUST 消失；「看過」＝窄螢幕上從那一條切走，或下次打開（寬螢幕兩條都在畫面上，標記在這次造訪裡一直顯示）。
  第一次進來的讀者 MUST 不顯示標記。
- **FR-005**: 打開交通頁時 MUST 落在：齒輪設定為「預設」時是上次離開時的那一條（第一次進來是熱點）；設定為「熱點」或「新文章」時一律是那一條。
- **FR-006**: 交通頁 MUST 有齒輪圖示的設定，提供「預設／熱點／新文章」三個選項，選擇在同一台裝置上保留。
- **FR-007**: 舊格式的報告分享連結 MUST 能正常打開交通頁，並照 FR-005 落地；本 spec 不把它對應到原本那份報告。
- **FR-008**: 新文章那一條 MUST 不標示文章被哪份報告引用：不顯示 ★，也不套用因被引用而來的加強樣式。
- **FR-009**: 測試殘留的報告 MUST 不出現在熱點那一條。
- **FR-010**: 熱點那一條的每個焦點事件 MUST 可以就地展開，顯示那篇的摘要與原文連結；預設收合。只呈現報告列出的焦點事件，
  不列出沒列成焦點事件的其餘來源。
- **FR-011**: 每份報告 MUST 寫出它是哪一次週報，以那次週報的週一日期表示（`week_start_date`）；字樣不得宣稱是產生當天
  （手動 dispatch 會在週一以外的日子產生，憲章 Operations & Deployment），由 T001 簽核時定。本 spec 不顯示來源新聞的發布日期區間。
- **FR-012**: 「有新的」標記與預設落地 MUST 在一般網頁裡完成，不需要安裝；讓站可以安裝成 PWA 與推播通知都不在本 spec（另有 BACKLOG）。
- **FR-013**: FFXIV 頁面 MUST 不受影響。
- **FR-014**: 兩條流、標記與齒輪設定 MUST 在亮色與暗色兩個主題下都讀得清楚；實作前先以兩個主題的實際畫面（412 px 加桌面）給 Luke 簽核。
- **FR-015**: 報告卡片的分享連結 MUST 打開熱點那一條、那份報告所在的那一批，並定位到那份報告，優先於 FR-005；
  連結同時帶批次與標題，之後產生新報告不改變它的指向；指到的報告不存在時照 FR-005 落地。

### Key Entities

- **熱點報告**：排程在每週一產生（也可能手動 dispatch），一批 1～3 份；有標題、所屬週報的週一日期、報告內文與一組焦點事件。產生方式本 spec 不改。
- **焦點事件**：報告引用的來源文章；報告知道它，文章不知道自己被引用。
- **新文章（buffer）**：依收集週次分組；同一篇文章只屬於一個收集週。
- **讀者的本機記錄**：每一條流上次看過的時間、上次離開時在哪一條、齒輪設定的選擇；只存在讀者這台裝置。

## Success Criteria *(mandatory)*

### SC-001 兩個時間軸分開（本 spec 的主要目標，實測）

上線後在 412 px 與桌機寬度各打開一次：新文章那一條抽 W44、W45 兩個週次，熱點報告 0 份、被引用的標示 0 個；
熱點那一條看得到最新一批，且能切到更早的批次；切換一條的導覽，另一條不動。

### SC-002 「有新的」標記算得對（實測）

用一份記錄了「上次看過」時間的本機狀態打開，兩條的標記與該時間之後實際新增的報告數、文章篇數一致；看過之後標記消失。
跨好幾個週次的情況（上次看過是 3 週前）也一致。「實際新增」用與實作不同的來源算（資料庫唯讀查詢 `created_at` 晚於基準的列數），
比對時本機沒有收起任何來源。

### SC-003 打開時落在對的那一條（實測）

US3 的四個情境（第一次、記得上次、固定熱點、固定新文章）各試一次，加上一個舊格式的分享連結：5／5 落在 FR-005 規定的那一條，0 次錯誤或空白頁。
另外，55 份真報告各自從卡片產生的新分享連結，打開後都定位到同一份報告：55／55（含同名報告不混淆）。

### SC-004 熱點那一條收錄全部真報告、不含測試殘留（實測）

熱點那一條瀏覽得到的報告數＝真報告數（2026-11-03 是 55 份），測試殘留 0 份。
