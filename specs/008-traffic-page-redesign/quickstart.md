# Quickstart: 驗證交通頁可讀性重設計

純前端改動，本地以靜態站方式驗證；後端（Worker/Supabase）沿用既有部署。

## 起站

```bash
# 於 repo 根目錄，用任一靜態伺服器服務 pages/
python3 -m http.server 8000 --directory pages
# 瀏覽 http://localhost:8000/traffic/
```

`pages/traffic/index.html` 內 `window.__API_BASE__` 指向線上 Worker（`https://garyu-news-scraper.lukeking0325.workers.dev/api`），故本地頁面讀的是線上資料，無需起後端。

## 逐項驗證（對應 FR / 使用者故事）

### US1 統一週導覽（P1）
1. 開 `/traffic/` → 僅顯示**最新一週**的深度分析與新聞列表（非全週堆疊）。
2. 確認週導覽**位於深度分析之上**。
3. 點較舊的某週 → 深度分析與新聞列表**同時**換成該週。
4. 找一個「只有深度分析、無新聞」（或反之）的週 → 有資料區正常、另一區空狀態、無報錯。

### US2 深度分析卡片（P2）
5. 任一深度分析 → 三軸分區清楚、關鍵指標（交織度分布）凸顯、焦點事件連結可點、`[1][2]` 引用可對應。

### US3 新聞密集列（P3）
6. 新聞列表為時間序密集列（來源色標＋標題＋相對時間），點標題可展開來源摘要 / 前往原文。
7. 關鍵字搜尋、標記過時仍可用。

### US4 深度分析分享（P3）
8. 某則深度分析按分享 → 取得 `?week=...#topic-...` 連結。
9. 另開該連結（或無痕）→ 載入後直接定位到該週該主題。
10. 失效連結（改成不存在的 week/topic）→ 回退最新一週、不報錯。

### 不回歸
11. 開 `/ffxiv/` → 重要度徽章、tags、分享等行為與改版前一致。
