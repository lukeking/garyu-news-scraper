# Feature Specification: 交通頁可讀性重設計（Traffic Page Readability Redesign）

**Feature Branch**: `008-traffic-page-redesign`  
**Created**: 2026-06-08  
**Status**: Draft  
**Input**: User description: "交通頁可讀性重設計：上方深度分析熱點報告與下方 buffer 新聞列表隨時間累積越來越難讀。統一週導覽同時驅動兩區並上移、去條列化的深度分析版面、更易快速一覽的新聞列表、深度分析的 LINE 分享（需 deep-link 到某週某主題）。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 以單一週導覽瀏覽某一週的完整週報 (Priority: P1)

讀者打開交通頁時，預設只看到「最新一週」的內容：該週的深度分析在上、該週的新聞列表在下。頁面頂端有**單一**週導覽控制項；讀者切換到某一週時，深度分析與新聞列表**同時**切換成那一週，彼此一致，不會跨週混雜。

**Why this priority**: 這直接解決核心痛點——目前所有週的深度分析全部堆在同一頁、越積越長，且週導覽只控制下半部、讀者分不清哪則屬於哪一週。把可見內容收斂到「一次一週」是讓整頁重新可讀的最小必要改動；其餘改善都建立在這個結構之上。只實作這一條，頁面就已經是可用的 MVP。

**Independent Test**: 載入頁面 → 只顯示最新一週的深度分析與新聞列表；點選較舊的某一週 → 上下兩區一起換成那一週的內容；確認沒有其他週的報告或新聞同時出現。

**Acceptance Scenarios**:

1. **Given** 系統已有多週的深度分析與新聞，**When** 讀者首次載入交通頁，**Then** 僅顯示最新一週的深度分析與新聞列表，且頁面標示出目前檢視的是哪一週。
2. **Given** 讀者正在看最新一週，**When** 讀者從頂端週導覽選擇較舊的一週，**Then** 深度分析區與新聞列表區同時更新為該週內容。
3. **Given** 頁面頂端的週導覽，**When** 讀者檢視版面順序，**Then** 週導覽位於深度分析區之上（即同時位於它所控制的兩個區塊之上）。
4. **Given** 某一週只有深度分析報告、但其新聞列表已因過期而清空（或反之），**When** 讀者切換到該週，**Then** 有資料的區塊正常顯示、無資料的區塊顯示明確的空狀態說明，頁面不報錯。

---

### User Story 2 - 深度分析以更易讀的版面呈現 (Priority: P2)

讀者閱讀深度分析時，內容以分段、有層次、可掃讀的形式呈現，而不是一長串生硬的「欄位：值」條列。重點結論能被一眼抓到，論述讀起來連貫。

**Why this priority**: 深度分析是這頁最有價值的內容，但目前的逐行表單式排版讀起來生硬。US1 完成後頁面已可用，US2 進一步提升最重要內容的閱讀品質，價值高但非阻斷性。

**Independent Test**: 開啟任一則深度分析 → 內容呈現為有標題層次、可掃讀的段落式版面，而非平鋪的標籤：值清單；讀者能在不逐行細讀的情況下抓到該則的主要結論。

**Acceptance Scenarios**:

1. **Given** 一則深度分析報告，**When** 讀者檢視它，**Then** 三個分析軸（事故因果、政經審查、官方論述偏誤）以清楚的視覺層次分區呈現，彼此一眼可分。
2. **Given** 報告中的關鍵結論（如交織度分布、代表個案），**When** 讀者掃視，**Then** 這些重點在視覺上被凸顯，不與次要細節同權重平鋪。
3. **Given** 報告含有引用來源標記（如 [1]、[2]），**When** 讀者閱讀，**Then** 來源標記與焦點事件連結維持可點擊、可對應。

---

### User Story 3 - 新聞列表可更快速一覽 (Priority: P3)

讀者瀏覽某週新聞列表時，能以更高密度、更快掃讀的版面快速判斷每則新聞的重點，而不需要為每則花同等的閱讀成本。

**Why this priority**: 提升次要區塊的瀏覽效率；在 US1、US2 之後錦上添花，對核心可讀性的影響較小。

**Independent Test**: 載入某週新聞列表 → 以可快速一覽的版面呈現，讀者能在短時間內掃過整週新聞並挑出想細看的項目。

**Acceptance Scenarios**:

1. **Given** 一週的新聞列表，**When** 讀者掃視，**Then** 每則新聞的關鍵資訊（標題、重要度、來源、時間）以一致且精簡的版面呈現，便於快速比較。
2. **Given** 既有的篩選與搜尋功能（重要度、標籤、關鍵字），**When** 版面改版後，**Then** 這些功能仍可正常運作。

---

### User Story 4 - 將某週某主題的深度分析分享到 LINE (Priority: P3)

讀者在某則深度分析上按下分享，分享出去的連結會直接開啟到「該週、該主題」的深度分析位置，讓收到連結的人看到的就是被分享的那一則。

**Why this priority**: 是使用者明確要求的功能，但價值與依賴都排在可讀性之後——它需要先有「可 deep-link 到某週某主題」的能力（由 US1 的週路由延伸而來）才有意義。

**Independent Test**: 在某則深度分析上觸發 LINE 分享 → 取得的連結在新環境開啟後，頁面直接定位到該週該主題的深度分析。

**Acceptance Scenarios**:

1. **Given** 一則深度分析報告，**When** 讀者按下 LINE 分享，**Then** 分享流程帶出一個指向「該週該主題」的可分享連結。
2. **Given** 一個指向某週某主題的深度分析分享連結，**When** 任何人開啟它，**Then** 頁面載入後直接定位到該週並顯示該主題的深度分析。
3. **Given** FFXIV 等未啟用分享的頁面，**When** 本功能上線，**Then** 那些頁面不受影響、不出現分享按鈕。

---

### Edge Cases

- 某週有深度分析報告但對應的 buffer 新聞已過期清空（或某週有新聞但尚未產生深度分析）時，週導覽如何呈現該週、各區如何顯示空狀態？
- 「深度分析的週」與「新聞列表的週」兩套週界定不一致時（兩者來源不同），統一週導覽以哪一套為主軸、如何對齊？
- 分享連結指向的週或主題已不存在（例如資料被清理）時，開啟連結後如何回退（導向最新一週並提示）？
- 完全沒有任何深度分析或任何新聞時，頁面如何呈現首次空狀態？
- 深度分析報告文字內含未預期格式（模型偶發跳脫既定輸出格式）時，新版面如何穩健降級而不破版？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 交通頁 MUST 提供**單一**週導覽控制項，且該控制項同時驅動深度分析與新聞列表兩個區塊——選擇某一週時兩區一起切換成該週內容。
- **FR-002**: 該週導覽控制項 MUST 位於深度分析區之上（即位於它所控制的兩區塊之上）。
- **FR-003**: 交通頁首次載入 MUST 預設顯示最新一週，而非一次列出所有週的內容。
- **FR-004**: 頁面 MUST 明確標示目前檢視的是哪一週。
- **FR-005**: 當某週僅有兩區之一有資料時，系統 MUST 正常顯示有資料的一區、對另一區顯示明確空狀態，且不得報錯或破版。
- **FR-006**: 深度分析 MUST 以分段、有視覺層次、可掃讀的版面呈現，避免一長串同權重的「欄位：值」條列；三個分析軸 MUST 在視覺上明確分區。
- **FR-007**: 深度分析的關鍵結論 MUST 在視覺上被凸顯，與次要細節區分。
- **FR-008**: 深度分析中的來源引用標記與焦點事件連結 MUST 維持可對應且可點擊。
- **FR-009**: 新聞列表 MUST 改為可快速一覽的版面，使讀者能高效掃讀整週新聞。
- **FR-010**: 既有的重要度篩選、標籤篩選、關鍵字搜尋功能 MUST 在改版後維持可用。
- **FR-011**: 系統 MUST 為每一則深度分析提供可 deep-link 到「該週該主題」的分享連結。
- **FR-012**: 開啟一個深度分析分享連結時，頁面 MUST 載入後直接定位到該週並顯示對應主題的深度分析。
- **FR-013**: 深度分析 MUST 可透過 LINE 分享（沿用既有的分享啟用開關，未啟用分享的頁面不受影響）。
- **FR-014**: 深度分析的呈現方式 MUST [NEEDS CLARIFICATION: 採「僅前端重新排版、維持現有分析輸出的固定逐行格式」，還是「同步放寬分析內容的產出格式以支援更自然的版面」？後者會牽動內容產出端與既有報告，前者範圍限於前端]。
- **FR-015**: 新聞列表的「快速一覽」版面方向 MUST [NEEDS CLARIFICATION: 偏向哪一種——更密集的精簡列、卡片網格、還是依重要度分組？目前方向未定]。
- **FR-016**: 既有的歷史深度分析報告 MUST [NEEDS CLARIFICATION: 一併套用新版面/新格式（需回填或重生既有報告），還是僅對日後新產生的報告生效？]。

### Key Entities *(include if feature involves data)*

- **週（Week）**: 週報的時間單位，是統一週導覽的選擇對象，串連同一週的深度分析與新聞列表。需要一套一致的「週」界定來對齊兩區。
- **深度分析報告（Deep-Analysis Report）**: 一週一主題的聚合分析，含三個分析軸、來源引用與焦點事件連結；是去條列化重排與 deep-link 分享的對象。
- **新聞項目（News Item）**: 新聞列表中的單則新聞，含標題、重要度、來源、時間等可供快速一覽的屬性。
- **深度分析分享連結（Shareable Deep-Link）**: 指向「某週＋某主題」深度分析的可分享 URL，是 LINE 分享與定位開啟的依據。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 交通頁首次載入時，畫面上同時呈現的深度分析報告數量被收斂到單一週的範圍內，不再隨歷史週數累積而無上限增長。
- **SC-002**: 讀者可在 1 次操作內，將深度分析與新聞列表一起切換到任一指定週。
- **SC-003**: 讀者無需逐行細讀，即可在一眼之內辨識出某則深度分析的主要結論與三個分析軸的分區。
- **SC-004**: 讀者可在不開啟每則新聞詳情的情況下，於一個畫面範圍內掃讀並比較整週多則新聞的重點。
- **SC-005**: 任一則深度分析皆可被分享，且收到連結者開啟後直接看到被分享的那一則（該週該主題），無需自行尋找。
- **SC-006**: 改版後，既有的篩選、搜尋與焦點事件連結等功能維持可用，無功能退化。

## Assumptions

- 統一週導覽複用文章列表側既有的週導覽模式作為基礎，以「新聞列表的週」為主軸對齊深度分析；當深度分析另有其週界定時，以可對齊的方式映射（細節待規劃階段確認）。
- 本次為前端版面與瀏覽結構的重設計，外加為支援深度分析分享/定位所需的最小路由與資料存取調整；不更動爬蟲、收錄、去重、評分等後端 pipeline 邏輯。
- 深度分析的內容仍由既有的分析流程產生；是否調整其產出格式取決於 FR-014 的釐清結果。
- 分享沿用既有的「是否啟用分享」開關，FFXIV 等未啟用頁面不受影響。
- 歷史深度分析報告的來源文章仍可取得（已分析的文章不在過期清理範圍內），故 FR-016 若選擇回填/重生在資料上可行。
- 預設檢視為最新一週；較舊週透過週導覽進入。

## Dependencies

- 既有交通頁前端（深度分析渲染、週導覽、新聞列表渲染、文章分享機制）。
- 既有 API 對「依週查詢」深度分析與新聞列表的支援。
- 既有的深度分析資料來源（每週每主題的報告與其來源連結）。
