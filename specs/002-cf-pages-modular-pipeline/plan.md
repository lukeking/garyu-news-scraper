# Implementation Plan: Separate CF Pages + Modular Pipeline

**Branch**: `002-cf-pages-modular-pipeline` | **Date**: 2026-05-04 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `specs/002-cf-pages-modular-pipeline/spec.md`

## Summary

Deliver two ordered improvements to the Garyu News Scraper pipeline. First (US1): parameterize `publisher.py` so each content type writes to its own output directory, and add a second Cloudflare Pages deploy workflow for the FFXIV site — giving traffic and FFXIV readers independent URLs with zero coupling between their deployments. Second (US2): introduce a `src/pipeline/` sub-module layer with a `Category` protocol so each content type is a self-contained orchestration unit, making new categories addable with one new file plus a one-line registration.

## Technical Context

**Language/Version**: Python 3.11  
**Primary Dependencies**: existing — google-generativeai, supabase-py, feedparser, beautifulsoup4, requests  
**Storage**: Cloudflare Pages (static file output, per-content-type directory) + Supabase PostgreSQL (centralized article persistence)  
**Testing**: No automated test suite; verification via local `python main.py` and manual GitHub Actions run  
**Target Platform**: GitHub Actions runner (ubuntu-latest) + Cloudflare Pages (static hosting)  
**Project Type**: Data pipeline / static site generator  
**Performance Goals**: Full pipeline completes ≤15 min on GitHub Actions  
**Constraints**: Cloudflare Pages free tier (unlimited projects); no new paid APIs; backwards-compatible with traffic-only mode  
**Scale/Scope**: ~30 articles/week across 2 content types; 2 static sites; no concurrent pipeline runs

## Complexity Tracking

| Violation | Why Needed | Simpler Alternative Rejected Because |
|-----------|------------|-------------------------------------|
| `src/pipeline/` sub-module (Principle V) | Enables category isolation and third-category extensibility without modifying existing modules | Single-file `main.py` growth: already at 87 lines, would become 150+ lines with per-category logic; harder to test categories in isolation |

## Phase 0: Research

All research complete. See [research.md](research.md) for full decision log.

**Resolved decisions**:
1. Publisher parameterization → `output_dir` + `site_url` params on `publish()` (backwards-compatible)
2. FFXIV deploy workflow → new `deploy-pages-ffxiv.yml`, same pattern as `deploy-pages.yml`
3. Category module boundary → thin wrappers calling existing stage functions
4. CF Pages free tier → unlimited projects, no cost concern
5. Collect decomposition → `collect_by_type(content_type)` added to `collector.py`
6. Supabase write scope → centralized in `main.py` after all categories run
7. Category module location → `src/pipeline/` (not `src/scrapers/`, which is reserved for collector sub-modules)

### US2 — Modular Pipeline (P2)

**New `src/pipeline/base.py`**:
```python
from typing import Protocol, runtime_checkable

@runtime_checkable
class Category(Protocol):
    name: str
    content_type: str
    max_articles: int
    output_dir: str
    site_url: str

    def collect(self) -> list[dict]: ...
    def filter(self, raw: list[dict]) -> list[dict]: ...
    def analyze(self, articles: list[dict]) -> list[dict]: ...
    def publish(self, articles: list[dict]) -> str: ...
```

**New `src/pipeline/traffic.py`**:
```python
class TrafficCategory:
    name = "traffic"
    content_type = "traffic"
    max_articles = 20
    output_dir = "pages/traffic"
    site_url = os.environ.get("SITE_URL", "https://lukeking.github.io/traffic-issue-scraper")

    def collect(self):
        from src.collector import collect_by_type
        return collect_by_type("traffic")

    def filter(self, raw):
        from src.filter import filter_and_deduplicate
        return filter_and_deduplicate(raw)[:self.max_articles]

    def analyze(self, articles):
        from src.analyzer import analyze_all
        return analyze_all(articles)

    def publish(self, articles):
        from src.publisher import publish
        return publish(articles, output_dir=self.output_dir, site_url=self.site_url)
```

**New `src/pipeline/ffxiv.py`**: Same pattern as `traffic.py` with `content_type="ffxiv"`, `max_articles=10`, `output_dir="pages/ffxiv"`, and appropriate `site_url`.

**New `src/collector.collect_by_type(content_type)`**:
```python
def collect_by_type(content_type: str) -> list:
    all_articles = collect_all()
    return [a for a in all_articles if a.get("content_type", "traffic") == content_type]
```

*Note*: Calls `collect_all()` internally. Efficiency: both categories run `collect_all()` independently, fetching sources twice. Acceptable at current scale (weekly run, ~5 sources). Can be optimized in a future refactor if needed.

**Updated `main.py`**:
```python
from src.pipeline.traffic import TrafficCategory
from src.pipeline.ffxiv import FFXIVCategory

CATEGORIES = [TrafficCategory(), FFXIVCategory()]

def main():
    all_analyzed = []
    for cat in CATEGORIES:
        try:
            raw      = cat.collect()
            filtered = cat.filter(raw)
            analyzed = cat.analyze(filtered)
            cat.publish(analyzed)
            all_analyzed.extend(analyzed)
        except Exception as e:
            logger.error("[%s] category failed: %s", cat.name, e)

    _save_to_supabase(all_analyzed, week_id)
    # KB MISS summary unchanged
```
