## CI 與測試

### 不要直接把整合測試加進 CI

原出處：GNS-001「CI gating」的 L2（PR #77／#78，2026-07-27）。

整合測試會寫正式 Supabase。直接開會分岔成兩條爛路——
不給憑證則測試 skip、拿到**假綠燈**（latent 失敗繼續躲著）；給憑證則**每個 PR 汙染正式資料庫**，
就是 2026-07-21 那件事乘以 N。

之後 PR #79 讓 `tests/integration/conftest.py` 對非本機主機 fail closed（GNS-002），本機要跑的步驟在
`CLAUDE.local.md`「測試」。

### 決策型測試：名稱與失敗訊息帶上決策出處與重開條件

原出處：同上（使用者提出的限制）。

把決策寫成測試**並不能讓決策免於腐朽**。有人為了改核心邏輯順手調整測試時，
若測試沒記錄「什麼絕對不能動」，約束會無聲死掉——而且對方會真心認為自己在修一個過時的測試。

本 repo 已有現成反例：`test_filter_attaches_category_and_score` 在有憑證環境長期 fail，
處理方式是標成 latent 繞過，**一個已經爛在原地的測試**。

所以：測試贏過註解的地方**只有一個**，是讓違反的那一刻可見；它不會讓決策變永久，
沒有東西能做到那件事。決定會不會腐朽的不是媒介，是**那個東西有沒有記錄自己的重開條件**。
因此若要寫「決策型測試」，測試名稱與失敗訊息 MUST 帶上決策出處與重開條件，
讓對方必須**自覺推翻一個決策**而不是**修一個壞掉的測試**。
結構性補強只有 CODEOWNERS／path-scoped required review——不是防止刪除，
只是讓沉默的那條路變貴。

## 選材與相關性 token 表

### 成本線：分群與選材在「每日零 AI」那一側

原出處：「機車事故熱點的關鍵字選材離題」（spec 012／PR #83）。

分群／選材目前在「每日零 AI」的純函數側。若用 LLM 判相關性會把成本推過那條線
——先想清楚能不能用純規則（token 白／黑名單＋來源降權）解掉大部分，把 LLM 留給真的難判的。

### `碾` ≠ `輾`：子字串規則對同義異形字是盲的

原出處：GNS-010「機車事故 require 表漏抓真事故」（PR #97）。

表裡有 **`碾`**，但台灣媒體慣用 **`輾`**——不同字，`碾` 抓不到 `輾`。
這類「同義異形字」是純子字串規則的系統性弱點，不是調參能解的個案。

### 不要直接把「車禍」加回 require 表

原出處：同上。

它是 T012 **刻意移除**的，`categories_traffic.yml`
的註解記著消融理由：獨撐 on-topic = 0（它抓到的 7 篇全有別的 token 也抓到），卻獨力製造
2 個 false positive（「車禍線上律師」是頻道名、「險釀車禍」是險象）。
把 `車禍` 加回來會同時撿回誤殺與撿回舊的 false positive，是走回頭路——**先讀那段註解再動手**。

## `auto_kb` 的測試

原出處：GNS-012「`auto_kb` 的 `call_gemini` 與 Step 4 寫入無測試」（PR #108）。

- `GEMINI_API_KEY` 那道閘**刻意留 fail-fast**（沒有金鑰就整支中止），不要在補測試時
  順手改成「靜靜跳過」——那會讓排程失敗變成無聲。
- `auto_kb.py` 的 Step 2 有一個 `sys.exit(0)` 早退（沒有未知術語就結束），
  Step 5 的職責會把未知集清空因而觸發它——**這正是當初要求「跑真 `main()` 而非重寫邏輯」的原因**
  （PR #103）。新測試一律走 `run_main`，不要另外乾跑某個函式。
